# Hackathon Registration and Team Management Portal

A beginner-friendly full-stack college project that lets students register hackathon teams, invite teammates with a code, browse public team summaries, and view a team's member list. It uses HTML, CSS, Vanilla JavaScript, Node.js, Express, and Supabase PostgreSQL.

## 1. Problem and objectives

Students often coordinate hackathon teams through scattered messages and spreadsheets. This portal keeps team registration and member information in one database-backed application.

### Roles
- **Student/team lead:** Create a team, receive a unique join code, and share it with teammates.
- **Student/member:** Join a team with its code and view team details with the code.
- **Administrator:** Use a server-configured admin key to list all teams and update a team's status. This is a simple project demonstration mechanism, not a full multi-user identity system.

### Implemented features
- Create a team and register the lead as the first member.
- Generate a unique team join code on the server.
- Join a team with a code; enforce member limit and per-team unique email.
- Search public team summaries by team name or college.
- View team details and member list with the join code.
- Admin-only endpoint to list all teams and update statuses.
- Supabase PostgreSQL persistence, input validation, rate limiting, security headers, responsive design, and a health check.

### MVP limitations
This educational MVP does not implement individual accounts, email verification, password reset, payment, file uploads, judging/scoring, or automated email. The team code is a shared secret, not proof of personal identity. Anyone who knows a code can view member details. Do not use real sensitive data. For production, add Supabase Auth, per-user authorization and appropriate RLS policies before exposing private data.

## 5. Supabase database setup
1. Sign in at https://supabase.com and create a new project.
2. Save the database password securely; do not put it in source code.
3. Open the project's **SQL Editor**.
4. Open `database/schema.sql` in VS Code, copy all its contents, paste into SQL Editor, and run it.
5. Open **Table Editor** and verify `hackathon_events`, `teams`, and `team_members` exist. The SQL creates one example event.
6. In project settings, find the project URL and server-side service-role/secret key in the API keys section. The exact dashboard labels can vary. Use only a server-side key in `backend/.env`. Never place it in `frontend/`, commit it, or share it in screenshots.

The SQL enables RLS and intentionally creates no public policies. The Express backend uses the privileged server-side key, so every endpoint must enforce its own checks. Keep the backend key private. The admin key protects the admin endpoints but does not replace proper user authentication for a production app.

## 6. Environment variables
1. In `backend/`, copy `.env.example` to a new file named `.env`.
2. Replace the placeholder values:

```env
PORT=3000
NODE_ENV=development
SUPABASE_URL=https://YOUR-PROJECT-ID.supabase.co
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SIDE_SECRET_KEY
ADMIN_API_KEY=replace-with-a-long-random-secret-for-admin-endpoints
```

Generate an admin secret in a terminal using Node:

```powershell
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```

Copy the output into `ADMIN_API_KEY`. Keep `.env` private. `.env.example` documents variable names but contains no working credentials.

Open the project folder in VS Code. Select **Terminal → New Terminal** and run these commands from the `backend` directory:

```powershell

npm install
npm run dev
```

Expected output:


Open http://localhost:3000 in your browser. Keep the terminal open while using the application. To stop the server, press `Ctrl+C`.

For a normal start instead of auto-reload, run `npm start` from `backend/`.

## 8. How the application works
1. Browser loads HTML, CSS, and JavaScript served by Express from `frontend/`.
2. `frontend/app.js` uses `fetch()` to call `/api/...` endpoints.
3. Express validates the request and calls Supabase through `backend/supabase.js`.
4. PostgreSQL constraints protect data relationships and prevent duplicate emails within a team.
5. The API returns JSON for the browser to display.

## 9. REST API reference
All endpoints return JSON. Errors use `{ "success": false, "message": "..." }`.

| Method | Path | Purpose / input | Access | Success / common errors |
|---|---|---|---|---|
| GET | `/api/health` | Check server and DB connection | Public | 200 `{success:true,message}`; 503 database unavailable |
| GET | `/api/events` | Get latest event details | Public | 200 `{success:true,event}` |
| GET | `/api/teams` | List public team summaries; optional `?search=...` | Public | 200 `{success:true,teams}`; 500 DB failure |
| POST | `/api/teams` | JSON: `name`, `college`, `projectIdea`, `leadName`, `leadEmail`, optional `memberLimit` | Public | 201 `{success:true,message,team}`; 400 invalid data, 403 closed registration, 409 duplicate lead on team |
| POST | `/api/teams/join` | JSON: `joinCode`, `fullName`, `email` | Public with team code | 201 `{success:true,message,team}`; 400 invalid input, 404 code not found, 409 full team or duplicate email |
| POST | `/api/teams/lookup` | JSON: `joinCode` | Public with team code | 200 `{success:true,team,members}`; 400 missing code, 404 unknown code |
| GET | `/api/teams/admin/all` | List teams and member details | Admin `x-admin-key` header | 200 `{success:true,teams}`; 401 missing/invalid key, 503 admin key not configured |
| PATCH | `/api/teams/admin/:id/status` | JSON `{ "status":"registered" }` or `submitted` or `cancelled` | Admin `x-admin-key` header | 200 `{success:true,team}`; 400 invalid status, 401 invalid key, 404 unknown team |

The API does not implement team edit/delete or a student login system. Do not assume those features exist.

### Admin endpoint example
Use a REST client or PowerShell after setting `ADMIN_API_KEY` in `.env`:

```powershell
$headers = @{ "x-admin-key" = "YOUR_ADMIN_API_KEY" }
Invoke-RestMethod -Uri "http://localhost:3000/api/teams/admin/all" -Headers $headers
```

Do not put the admin key in browser JavaScript or HTML.

## 10. Manual testing checklist

| Test | Action | Expected result |
|---|---|---|
| Server/database | Open `http://localhost:3000/api/health` | `success: true` if Supabase settings and schema are correct |
| Create team | Fill all required fields and submit | Team is stored; unique join code appears |
| Required fields | Submit create form empty | Browser validation prevents submission |
| Invalid email | Enter an invalid email | Browser/backend reject it |
| Join team | Use a valid code and a new email | Member is added |
| Invalid code | Join using a random code | Friendly not-found error |
| Duplicate email | Join the same team twice with same email | Conflict message; no duplicate row |
| Team capacity | Fill team to its configured limit, then join again | API rejects the extra member |
| Search | Search for a team or college | Matching public summaries appear |
| Lookup | Enter valid team code | Team details and member list appear |
| Privacy | Inspect public team list | No join codes or member email addresses are included |
| Admin key | Call admin endpoint without key | 401 response |
| Invalid status | Admin submits unsupported status | 400 response |
| Mobile layout | Resize browser to phone width | Forms and cards stack without horizontal scrolling |
| Database unavailable | Temporarily use an invalid URL in local `.env`, restart | Health endpoint returns 503; restore correct URL afterward |

No remote Supabase database or browser session has been tested for you. Run these checks with your own project credentials.

## 11. Troubleshooting
- **Missing environment variable:** Confirm `backend/.env` exists and variable names match `.env.example`; restart Node after changing it.
- **Database connection error:** Check project URL, server-side key, internet connection, and whether the SQL schema was executed.
- **Table not found:** Run `database/schema.sql` in the correct Supabase project's SQL Editor.
- **Port in use:** Change `PORT=3001` in `backend/.env`, restart, and open `http://localhost:3001`.
- **`npm` is not recognized:** Install Node.js LTS, then close and reopen the terminal.
- **Changes do not appear:** Refresh the browser; ensure the terminal is running the project you edited.
- **Admin endpoint returns 503:** Set an `ADMIN_API_KEY` of at least 32 characters in `.env` and restart the server.
- **A form says registration closed:** In Supabase Table Editor, check `hackathon_events.registration_open`.

## 12. Git and GitHub upload
Create an empty repository on GitHub, for example `Hackthon-`, without adding a README or license if you already have local files. In VS Code terminal, run from the **root project folder**:

```powershell
git init
git status
git add .
git status
git commit -m "Build Hackathon Registration and Team Management Portal"
git branch -M main
git remote add origin https://github.com/nagetipoojitha982-lab/Hackthon-.git
git push -u origin main
```

If that repository URL is not yours or does not exist, replace it with the HTTPS URL copied from your own GitHub repository. If `origin` already exists, inspect it with `git remote -v` and update it using `git remote set-url origin YOUR_REPOSITORY_URL` instead of adding it twice.

Before `git add .`, confirm `backend/.env` and `node_modules/` are ignored. `.env.example` should be included. After pushing, open the repository page and verify the `frontend`, `backend`, `database`, and `README.md` files are present.

**Important:** `.gitignore` does not erase a secret already committed. If you accidentally publish a database key or password, rotate it immediately in Supabase and clean the repository history as appropriate.

## 13. Security notes and future improvements
- Keep the Supabase service-role key and admin key only in server environment variables.
- Public team summaries intentionally omit join codes and emails.
- A shared join code is not strong personal authentication; treat it like a password and only share it with teammates.
- For a real public deployment, add Supabase Auth, per-user ownership checks, stronger authorization, audit logging, and a carefully tested RLS design before exposing private member details.
- Other possible improvements: event registration deadlines, team editing, email verification, project submissions, judging and scoring, CSV exports, and automated tests.
